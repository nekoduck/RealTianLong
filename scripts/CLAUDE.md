# scripts/
> L2 | 父级: /CLAUDE.md

本地开发基础设施与演示工具。不含引擎逻辑：只准备环境，或把引擎跑一遍给人看。

成员清单
neo4j_local.sh: 下载并启动 Neo4j Community（仅监听 127.0.0.1，限定堆与页缓存），要求预设 NEO4J_PASSWORD；供契约测试与 `--store neo4j` 持久化游玩
make_colab_notebook.py: notebooks/train_colab.ipynb 的唯一源头（单元格以 Python 字符串维护，可审阅可测试）；--commit 填入固定提交生成交给 Colab 的那一份，仓库里的版本不填（tests/test_notebook.py 核对一致）
play_demo.py: 按固定指令序列录制一局（段誉的原著路线，默认旧版 wuliang-duanyu，写到 docs/demo/wuliang.md；普通人版另写 wuliang_c.md，不覆盖旧录像）：每回合玩家所见的叙述 / 内核裁定的全部事件 / NPC 各自理由，结尾对照玩家以为与真相；叙述经 CachedLLM 缓存，重跑不再花费调用
bench_gm.py: 主持层评测（设计 §7 与“评测细则”），命令行 --out DIR [--llm auto|scripted|none] [--baseline] [--judge] [--turns N] [--limit K] [--probes FILE] [--latency-sim]，也是可导入的库；探针文件的 variant 决定场景（SCENARIOS；没写的是旧版，--probes scripts/bench_probes_duanyu.json 即 run1–6 的评测、与改名前的缺省行为一致），把 GameSession 当黑盒逐回合跑（会话新字段一律 getattr，缺了就退化），每条探针从全新会话出发、先走 setup、异常逐条记下不中断；按 TurnReport 与世界真相算 L1/L2（挂钟 + on_text 首字）、R4、C1（kernel.violations）、C2/R1（声称之物在真相里成立且归到玩家名下）、G1、N1、F2（4-gram）、P1（词法），另接 bench_metrics 的 B1/E1/NAME/SEAM/FPD/R5/F3/TOK/END（不进盲评的留守型、夜遁型整局只量 END/E1/B1），写 bench.json 与带门槛 PASS/FAIL 的 report.md；auto 用真模型且缓存关闭、无密钥退回 scripted，scripted 的报告注明不作验收依据，--latency-sim 按公开分布模拟延迟并标注“模拟”；本引擎走到结局时把终章（收束 + 真相揭晓或纪事）一并记下，只把收束交给整局盲评（真相揭晓与“那一夜你没看见的事”是落幕后另起的卡片，对照组没有对应物）；盲评 A/B 先后按面板（bench_rival.PANELS 轮流换边，旧版照旧按种子）
bench_rival.py: bench_gm 的模型侧（单独成文件只为不超 800 行，不依赖 bench_gm）：PureLLMGM 纯模型主持人对照组（由场景生成的全知世界圣经——玩家那一行的目标用玩家自己的口吻（与主持层场外问答同一张 runtime/gm.PLAYER_GOALS），不借 NPC 的行事语义；场景带驱力（普通人版）时另写玩家扮演谁（普通人、不会武功）、各 NPC 的性情与行事（Drive.gloss）、可用的驱力台词、由时刻与驱力时间窗推出的时间表、外貌称呼规则、结局的时钟与变体，旧版逐字不变——+ Jenova 公开主持规矩 + 每回合全量对话、流式计时）、独立评审（premise_prompt / pairwise_prompt（pair_note：只在普通人版写明“玩家不是段誉”不算错），严格 JSON，parse_verdict 容忍坏输出、拿不准判无效；盲评顺序：run7 起的 3 个面板 PANELS（panel_name：两个种子 + 玩家代理）从派生起点轮流换边、两种先后都出现，旧版照旧由种子固定打乱；epilogue_story 只取终章的收束，真相揭晓与纪事不进盲评）、--llm scripted 的离线脚本模型（解释器 JSON 兼容新旧 schema、照事实清单写叙述、顺着玩家的主持人，模拟首字 0.6/0.3 s 与 250 字/秒）
bench_metrics.py: bench_gm 的新指标（plan §8.3，单独成文件只为 bench_gm 不超 800 行）：Metered 包一层模型（叙述与解释器各一层）、记下每次调用的提示词字数与原始回复，snapshot / observe 在 engine_turn 前后读会话（看点、空转、相识账本（session_state 的 names——Acquaintance.to_state() 的 known 表——或会话 _acq.of(玩家)，缺即“不可得”）与越账本的名字、缝、当面搭话与回应（回应须真的交付：正文里有他的引语或照录了原话开头，只出现名字不算；另附同 B 的词法口径）、提示词 token（叙述 + 解释器，分开列中位））；b1 / e1 / names / seam / fpd（tests/data/gate_corpus.json 的 FP 条目经 language.gate.violations）/ r5 / f3（按“某某道：“……””抽引语、3-gram ≥0.6）/ tok / end 只读回合记录（手造记录即可测）；engine_extra / baseline_extra 给两边的一览（对照组没有内核与账本：R5 / F3 / END 用词法——结局标题去掉标点空白再比（ending_of），其余不适用）
bench_latency.py: bench_gm --latency-sim 的延迟模拟（plan §8.4 与 §5）：SimLLM 按公开分布抽样首 token（快模型 0.4–0.6 s、每秒 500 字；叙述模型 p50 2.2 s、p95 5.3 s，每秒 60 字；提示词超过 TOK_REF 按同一模型加预填充——对照组的首 token 随 TOK 增长即来自这里），抽样由 derive_seed 派生（确定性），scale 同比缩放一切等待（含会话的先声时限）；sim_llms() 给出与 scripted_llms 同样的四个角色；报告必须标注“模拟”
bench_online.py: 在线代理评测（设计 §8.4，没有模型密钥时由只看这一次调用的隔离代理替模型作答），python scripts/bench_online.py {keys|step|answer|assemble|dump} DIR [KEY] [--world wuliang|wuliang-duanyu] [--seed N] [--probes FILE] [--open-actions K]：step 用已有答案从头重放一个会话（同样的答案 → 同样的轨迹）、停在第一个没答的调用上打印其 system 与 prompt 并立刻退出，answer 以 stdin 追加答案；本引擎的键是 playthrough / playthrough_hall / playthrough_flee / 组:探针 ID，对照组（圣经 + 完整对话 + 新输入）的键加 B: 前缀、同一套 step / answer；运行目录按世界与种子分开（旧版种子 7 仍是 DIR 本身，其余 DIR/<world>-s<seed>，两个种子即对照组独立跑两次）；assemble 在全部 DONE 后拼出本引擎记录（额外整局进 extras）、按对照组的 B:* 回复（须全部 DONE；一个都没跑且是旧版种子 7 才取录制的 DIR/rival_answers.json，否则报出没跑完的键）回放纯模型主持人、写盲评面板（A/B 先后按面板轮流、终章只取收束）/评审提示词/报告，dump 写下一个会话的每次叙述调用；解释器按玩家原文取 interp_answers.json；也是可导入的库（run_key / rival_key 给定答案重放一个会话），重放时关掉迟到的先声（代理作答瞬时，它本不上场）；--ask-interp 时解释器缺答案也停下由代理作答（role=interp，附 schema，按玩家原文记进运行目录的 interp_answers.json，同一句话复用）
bench_player.py: 玩家代理模式（plan §8.4），python scripts/bench_player.py {step|answer|panel} DIR [A|B] [--world W] [--seed N] [--turns K]：隔离的“玩家”代理（第一次玩、谨慎而好奇的普通玩家，PLAYER_SYSTEM）只看本方看得见的正文，每回合写一句 ≤30 字的输入，最多 30 回合、到结局即停；A 本引擎（narrator / interp 由隔离代理作答）、B 纯模型主持人（rival）各一局；step 从头重放、停在第一个没答的调用上打印待答的角色与完整提示词，answer 以 stdin 追加该角色的答案（玩家超过 30 字拒收），panel 写盲评面板（A/B 先后按面板轮流换边、终章只取收束）与两边的结局（B 按标题词法、去标点空白）、A 的 B1/E1；也是可导入的库（game / recorded / record / panel），tests/test_bench_player 用 ScriptedLLM 替身跑通全流程
replay_drops.py: 闸门误杀排查，python scripts/replay_drops.py DIR [KEY] [--probes FILE] [--answers FILE] [--interp FILE] [--inputs FILE]：经 bench_online 在当前代码上重放录下的代理答案，逐条列出叙述者丢弃、略过与补上的句子并给出丢句数；--probes 的 variant 决定场景（缺省普通人版）；--inputs 以 JSON 字符串数组取代探针文件里的整局游玩（M1 出口条件：DIR 取 tests/data/run6、--probes 取 scripts/bench_probes_duanyu.json、--answers 取其 playthrough.answers.json、--inputs 取 tests/data/playthrough_duanyu.json，与测试重放同一份输入，探针改版不动它）；load_inputs() / replay() / dropped() 供 tests/test_replay_run6 钉住 M1 的误杀基线
sim_beats.py: 普通人版调参台（plan §7 M2），python scripts/sim_beats.py [--seeds 1-20|7,11] [--players ...] [--json FILE] [--check] [--jobs N] [--walk PROBES]：不接模型、模板模式，种子 × 五种脚本化玩家（被动等待、跟随段誉、撒谎者、抢帛卷的、夜里溜走的——只凭玩家自己的认知与时钟行事）逐回合跑真实会话，报告 B1（按场景识别器只算玩家感知到的看点）、段誉到达琅嬛/澜沧江的种子数、到达的结局、讨价还价是否成立、钟灵是否被制、各驱力兑现次数、E1（空转推进回合比例）；--check 按 GATES（跟随型 ≥16/20 目击 ≥8/11、跟随型与全体合计的 E1 各 ≤ 10%（逐脚本不设门槛）、被动玩家下段誉 ≥12/20 到琅嬛且 ≥8/20 到澜沧江、讨价还价 ≥16/20）判定；--walk 是进 run7 之前的走查核对（plan §8.1）：评测探针的三条整局在各种子上逐句落在有意义的状态上（CANON 规则说法 + WHEN 在回合开始时的真相上求值），落空或没接住即非零码退出；也是可导入的库（play / summarize / pooled_e1 / table / PLAYERS / walk / WALKED），tests/test_commoner 与 tests/test_bench_gm 按文件加载；结果表入库为 docs/results/sim_beats.md
bench_probes.json: bench_gm 的中文探针 v2（普通人版，"variant": "wuliang"，plan §8.1）：跟随型整局 38 句（跟着段公子从大殿到澜沧江畔，进盲评）、留守型与夜遁型整局各 24 句（守在剑湖宫骗走龚光杰、熬到天亮 / 夜饭换班时溜去山道下山；不进盲评，覆盖天亮与下山两种结局）、60 句花样输入（R4，带参考类别 expect）、20 句瞎编前提（C2）、12 句不可能的企图（R1）；玩家开场不认得的人按外貌称呼；每条可带 setup 铺垫与 require 前提，claim 为真相可检的声称（持有/学成/身处/交到/被制/受伤），assert 为词法旁证关键词，note 为评审的事实依据；三条整局在种子 7 与 11 上过 sim_beats --walk
bench_probes_duanyu.json: 旧版（段誉作玩家）探针：原 bench_probes.json 原样改名，顶层只加 "variant": "wuliang-duanyu"（摘要不含 variant，与 run1–6 相同）；--probes 指过来即复现 run1–6 的评测
