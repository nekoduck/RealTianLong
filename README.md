# RealTianLong

图世界文字游戏引擎：**规则内核裁定事实，每个角色经由自己的认知图理解世界**；GNN 预测行动后果，强化学习训练角色如何选择，LangGraph 编排多个角色的决策流程，向量库提供可检索的经历，LLM 只负责开放语义与文字表达。

> 预测不是事实，回忆不是现状，相信不等于真实，多个 agent 达成一致也不等于事情已经发生。
> 这四条边界在本仓库里被实现成了数据结构、接口与测试。

## 架构

```
                 ┌──────────────────────────── runtime/session：一回合 ────────────────────────────┐
玩家文本 ──▶ language/parser（规则优先，Gemini 兜底，只能引用玩家认识的实体）──▶ 结构化意图 ─┐
                                                                                              │
各 NPC：agents/npc_graph（LangGraph）                                                          │
  observe → recall(Qdrant) → propose(候选) → predict(GNN) → decide(RL/脚本) → express → 意图 ─┤
          ▲ 只经由 AgentPort 读自己的认知与回忆                                                 │
          │                                                                                   ▼
cognition/BeliefStore ◀── 感知折叠 ◀── runtime/WorldAuthority（唯一写入者，幂等 + 版本锁）◀── kernel.step（纯函数裁定）
          │                                   │
          │                                   ├─▶ persistence（内存 / Neo4j）：世界、事件、观察、命题与信念、outbox
          │                                   └─▶ memory/indexer ─▶ Qdrant（派生数据，可重建）
          ▼
language/narrator：只把玩家本回合的感知写成文字，过语义闸门才展示
```

| 组件 | 选型 | 职责 | 刻意不承担 |
|---|---|---|---|
| 世界规则内核 | 纯 Python（`kernel/`） | 前置条件、冲突结算（先手度排序）、时间、效果、感知、不变量 | —— 唯一裁定事实处 |
| 图数据库 | Neo4j（`persistence/neo4j_store.py`） | 实体/关系/事件/观察；命题节点与 `BELIEVES` 边分离“内容”与“谁相信” | 判断角色该做什么 |
| 图神经网络 | PyTorch Geometric（`learning/`） | 行动条件化的动态预测：成败、位置变化（含“未知”）、属性 | 未经内核校验改写世界 |
| 多智能体框架 | LangGraph（`agents/`） | 单角色决策图 + `Send` 扇出并行编排 | 用“讨论结果”替代世界规则 |
| 向量数据库 | Qdrant（`memory/`） | 按语义检索本人有权回忆的经历（服务端强制过滤） | 裁定物品当前位置 |
| 强化学习 | RLlib（`learning/rl/`） | 模仿学习初始化 + PPO，所有角色共享参数、各自观测 | 游玩中临时重训 |
| LLM | Gemini（`language/`） | 输入解析、对白润色、叙述润色；失败或未过语义闸门即回退模板 | 裁定事实、越过认知边界 |

## 设计验收用例：仓库钥匙

玩家在仓库，守卫在入口，船长在港口；钥匙在桌上、属于船长、匹配锁着的仓库门。

1. 玩家拿走钥匙 → 钥匙位置变化，**所有权不变，门仍锁着**。
2. 守卫隔一道门**只听到响动**，不知道是谁、做了什么；船长毫无感知，仍以为钥匙在桌上。
3. 守卫决定进去查看 → 环顾时发现**钥匙不在桌上**，但钥匙藏在玩家身上，**不知道谁拿走了它**。
4. 盘问无果后搜身，才知道钥匙在玩家身上 → 去港口报告船长 → 船长打听玩家下落 → 当面质问。

整条链路由 `tests/test_acceptance_warehouse.py` 与 `tests/test_agents.py` 逐段断言；NPC 的每一步都由各自的认知驱动自然涌现，没有剧本。

## 训练与结果

```bash
# 动态模型：环境视角（全知，含内力/锋利/淬毒/进度等机制变量）与角色视角（只看认知），按世界三分 训练/校准/测试
python -m tianlong.learning.train --view env   --worlds 1500 --epochs 25 --jianghu 0.5 --scroll-held 0.3
python -m tianlong.learning.train --view agent --worlds 1500 --epochs 25 --jianghu 0.5 --scroll-held 0.3
# 角色策略：模仿学习 → PPO → 留出世界评测（同一份 TaskConfig 贯通示范、PPO 的每个 env runner 与评测）
python -m tianlong.learning.rl.train --jianghu 0.5 --demo-episodes 200 --bc-epochs 3 --bc-smoothing 0.1 --entropy 0.03 \
    --ppo-iterations 40 --train-batch 3000 --eval-episodes 100 --env-runners 1 --seed 0 \
    --predictor-path artifacts/dynamics_agent.pt --out artifacts/rl/main_s0
# 训练期消融是另一次运行（--ablate-predictions true / --ablate-memory true），报告带逐世界记录
# 结果表：从机器可读报告生成（每张表写明 run_id、提交号、任务指纹与种子）；--pair 把两次运行在同一批留出世界上配对比较
python -m tianlong.learning.results artifacts/dynamics_*.json artifacts/rl/*/policy_ppo*.json \
    --pair artifacts/rl/main_s0/policy_ppo_s0.json artifacts/rl/noPred_s0/policy_ppo_noPred_s0.json --out docs/results/<运行名>/RESULTS.md
# 部署包：记下训练时的全部语义版本与文件哈希；游戏加载前逐项核对，策略配套的预测器随包决定
python -m tianlong.learning.bundle artifacts --predictor artifacts/dynamics_agent.pt --policy artifacts/rl/main_s0/policy_ppo_s0.pt
python -m tianlong --predictor gnn --policy learned --artifacts artifacts
# 剖析：先看清时间花在哪一段（GPU 只帮得上网络前向与学习器）
python -m tianlong.learning.profile --worlds 20 --out artifacts/profile.json
```

两个训练 CLI 都支持 `--workers N`（0 = 全部核）：世界生成、评测与模仿示范按世界/按局分给多个进程，结果与顺序执行逐项相同（有测试对照），并行度不进 run_id。速度主要取决于 CPU 核数——世界模拟、认知折叠与 GNN 预测都在 CPU 上；GNN 预测器对同一次决策的全部候选只构图、只编码一次（与逐候选计算逐项相同），训练期消融了预测的运行不再计算预测。

两个训练 CLI 都支持 `--resume true`：GNN 按轮续训（与不中断逐位相同），PPO 从最近一次保存的权重接续；换了配置的断点会被拒绝，`--resume` 本身不进 run_id。

**Colab**：更大规模与多训练种子在 Colab GPU 上跑同一套命令——[`notebooks/train_colab.ipynb`](notebooks/train_colab.ipynb)（由 `scripts/make_colab_notebook.py` 生成，`--commit <40 位提交>` 填入固定提交）。笔记本检出固定提交（代码来自 Drive 上的 git bundle 或 GitHub，从不嵌套克隆、从不静默用旧提交），按 `constraints.txt` 锁定版本安装，全量测试失败即停，按本机核数自动分配并行进程（速度取决于 CPU 核数；GPU 只用于 GNN 训练与学习器，显存需求远小于 16 GB——选每计算单元核数最多的运行时，不必选贵的 GPU），产物全部写进 `MyDrive/RealTianLong/runs/<运行名>/`，断线后重新“全部运行”会跳过已完成的阶段；私有仓库的令牌只经环境变量注入一次性请求头，不进 remote、git 配置与日志。

口径（见 `learning/rl/evaluation.py`、`learning/train.py`）：

- **可溯源**：每份报告与检查点带 manifest（提交号、工作区是否干净与未提交改动的哈希、全部语义版本——特征规格/属性/目标/奖励/候选规则/规则内核/观测布局、任务指纹、完整配置、训练与评测种子、依赖版本、设备）。报告是严格 JSON（算不出来的是 null）。跨种子汇总只合并同一提交、除种子外配置相同的运行。README 里的数字只从 `docs/results/` 下的报告生成。
- **部署**：`bundle.json` 记下训练时的全部语义版本与文件哈希；词表相同但规则、目标、奖励、候选规则或观测布局任一变了，游戏都会拒绝加载并列出不一致项（不做隐式迁移，要迁移就重训）。
- **动态模型**：指标按声明的预测目标逐项——位置召回叫 `holder_*`（不冒充“全部事实”）、布尔属性逐项、数值属性（进度、内力、点穴余时）给 MAE 对照“不变”、发现新实体与有效新观察数；成败的 Brier 对照**训练集**常数，温度只在独立的校准世界上拟合，测试世界只报告；`coverage` 报告每类机制在数据里出现了几次。
- **策略**：行为计数只读事件（改奖励权重不改计数）——搜身分“落空”与“无证据”、动手分得手/落空/被拒与“目标所驱（含为目标物品对自己认定的持有者）/还手护人/无端”、误指控、无效循环（只算确定性失败的重复；被招架/闪避后再出手另计随机重掷）；目标分**开局即满足**、**激活后新达成**、**持续目标守住**，并报达成用时与可达性。必报**永远等待**基线：一部分“达成”只是保持初态。
- **统计**：同一局里的角色互相影响，区间一律以**世界**为单位重采样；策略之间只在同一批世界上**配对**比较；世界少于 20 个不下结论；“没发现差异”不等于“等效”，等效要求整个区间落在事先声明的容许差内。训练期消融（`--ablate-predictions` / `--ablate-memory`，策略从头到尾看不到预测或长期记忆列；上线时同样置零）与测试期消融（训练时看得见、评测时置零）分开报告、分开解释；训练期消融与主实验用 `results --pair` 按世界配对。

#### 动态模型（600 个测试世界，从未参与训练与选轮）

数据规模：3000 个程序化世界（一半江湖化）× 24 步，按世界三分为 2100 训练 / 300 校准 / 600 测试，训练 40 轮。按校准损失选轮：角色视角选中第 21 轮，环境视角选中第 13 轮。角色视角的校准损失从第 21 轮的 0.308 升到第 40 轮的 0.344，选轮机制挡住了这段过拟合。

| 指标 | 角色视角 | 环境视角 | 基线 |
|---|---|---|---|
| 行动成败准确率 | 0.945 | 0.987 | 0.755（训练集多数类） |
| 成败 Brier（校准世界拟合温度后） | 0.035 | 0.007 | — |
| 位置变化召回 `holder_changed_recall` | 0.854 | 0.999 | 0（“什么都不变”） |
| 预测出的位置变化的精确率 | 0.905 | 1.000 | — |
| 未变的位置保持不变 | 0.995 | 1.000 | 1.000 |
| 本不知道却被预测成确定位置 | 0.001 | — | — |
| 属性变化预测正确 | 0.807 | 0.906 | 0 |
| 有效新观察数 MAE | 0.310 | — | 0.756（训练集均值） |
| 发现新实体：召回（精确率） | 0.261（0.548） | — | — |
| “确知不在原处、去向不明”召回 | 0.030（n=99） | — | — |

成败按操作分项的 Brier（越低越好）：

| 操作 | 角色视角 | 环境视角 | 训练集常数 |
|---|---|---|---|
| 移动 | 0.096 | 0.000 | 0.193 |
| 开锁 | 0.057 | 0.001 | 0.090 |
| 动手 | 0.152 | 0.113 | 0.250 |

如实结论：

- **角色视角与环境视角在成败预测上的差距，主要在移动上：角色看不到门锁没锁**。在同一批测试样本上，移动成败 Brier 0.096 对 0.000（n=3471），动手 0.152 对 0.113，开锁 0.057 对 0.001。
  属性与位置指标在两个视角下统计的对象不同，不能直接对比：角色视角的“上锁”变化（n=2059）多是认知变化，比如刚得知一扇门锁着；环境视角只算真正的上锁或开锁（n=67）。
  上一轮“角色模型开锁比常数还差”的问题已不存在：开锁 Brier 0.057，训练集常数 0.090。
- **动手有内核设定的随机性**：规则内核裁定胜负时，给双方的身手各加一个均匀扰动。环境模型看得到内力与锋利，动手 Brier 也只到 0.113（常数 0.250），“受伤”属性只对 0.694（n=291）。角色视角的 0.454（n=460）还叠加了看不到对方身手的影响。0.113 是不是下限，报告里没有测。
- **弱项多是稀有类别，但不全是**。
  - 稀有的：“确知不在原处”召回 0.030，训练集 323 例；“在此前不认识的容纳者那里”12 例全错，训练集 71 例；吸功、闪避在测试集上 0/7、0/3，训练集 8、7 例。
  - 不稀有的：“发现新实体”训练集有 3376 例，召回仍只有 0.261；“受伤”训练集有 1632 例，角色视角只对 0.454。
  - 报告只给阈值后的召回，分不清是没学会，还是角色视角下本来就猜不到。“定向生成数据能补上”只是待验证的假设。

如实结论：

1. **学得的策略远好于随机与永远等待，接近脚本示范者，但略低于它**。PPO 与模仿学习的目标达成率都是 0.602，示范者是 0.627。
   - PPO − 示范者：三个种子的点估计都为负（−0.0243 / −0.0081 / −0.0445），只有 s1 落在等效容许差内，s2 显著更差。
   - PPO − 模仿学习：s0、s2 等效，s1 不确定。
   - 报告里没有模仿学习与示范者的配对比较。
2. **PPO 比模仿学习更好斗，这是目前最需要修的行为问题**。每局无端动手从 0.13 / 0.19 / 0.06 次升到 0.54 / 0.68 / 0.78 次，无端动手占全部动手的比例从 0.077 升到 0.219。
   - 以 s0 为例（部署包用的就是它）：每局动手从 1.78 次升到 2.51 次，多出来的主要是无端（+0.41）和还手（+0.23），目标所驱只多 0.09 次。
   - 新达成（0.596 → 0.638）与持续目标守住（0.650 → 0.593）三个种子方向一致，但幅度很不均，报告也没有对它们做配对检验，所以这里不下“拿守护换一次性目标”的结论。
   - 平均回报从 −0.309 升到 −0.272，逐种子配对都不确定（0.0002 / 0.0578 / 0.0518）。
   - PPO 的无效循环集中在 s1，每局 2.64 次；s0、s2 只有 0.13、0.32 次；示范者与模仿学习为 0。
3. **世界模型的预测对目标达成率没有可测贡献，对回报也没有干净的证据**。
   - 测试时把预测列置零：s0、s1 的目标达成率仍在等效容许差内；平均回报降 0.0432 / 0.0638 / 0.0491，只有 s1 显著；无效循环三个种子都增加。
   - 但置零喂给策略的是训练时没见过的输入。这点下降更能说明“策略依赖了这一列”，而不是“预测带来了回报”。
   - 干净的对照是训练期消融：从头不给预测训练出的策略，与主实验配对的目标达成率差 −0.0081、平均回报差 0.0089，都不确定。
4. **去掉长期记忆，达成率与回报的差别不确定，但行为差别很大**。去掉记忆的 PPO 每局动手 5.60 次，其中无端 1.02 次；主实验三个种子每局动手 2.51–3.67 次，s0 无端 0.54 次。每边只有一个种子，分不清是记忆的作用还是种子差异。
5. **“不确定”不等于“没有用”**。这些区间只反映 100 个评测世界的抽样：目标达成率半宽约 0.04–0.06，平均回报约 0.07–0.08。训练种子之间的差异不在区间里。每个消融只有一个种子，真实的不确定性比区间更大。
6. **示范者守不住持续目标，而报告还分不清原因**。
   - 示范者守住持续目标 0.646（64/99），模仿学习照样学了过来（0.646 / 0.646 / 0.657）。
   - 永远等待的 0.970 是靠放弃全部一次性目标换来的（新达成 0/199），不是可达的上限。
   - 评测时同一局的所有角色都由被评策略驱动，守护目标被破坏也可能来自另一个角色追自己的目标。报告没有按目标类型和出手者拆分，分不清是示范者自己破坏，还是角色之间的目标冲突。
7. **“先探查”旋钮拉低了随机策略，但没有拉开示范者与学得策略的差距**。
   - 把 `hide_goal_items` 调到 1.0 后，脚本示范者 0.624（主任务 0.627），永远等待完全相同，PPO 0.632；随机策略则从 0.352 降到 0.279（新达成 0.417 → 0.327）。
   - 按现在的世界生成，这个旋钮只藏不在人身上、也不是钥匙的目标物品。
   - 它还不是一道能区分“会不会先打听、先搜查”的考题。

下一步（尚未实施）：

- **PPO**：模仿学习之后先单独预热价值头，加上相对模仿策略的 KL 约束，把无端动手计入惩罚。
- **报告**：按目标类型（护物、护人、守地）与破坏者拆分持续目标守住率，加上模仿学习 − 示范者的配对比较。有了这些，再决定是改示范者，还是在任务生成里控制目标冲突。
- **世界模型**：给“确知不在原处”“落到陌生人手里”“发现新实体”“受伤”这几个头补上 Brier 或按类学习曲线，分清“没学会”与“本来猜不到”，再决定是否定向生成数据。
- **“先探查”任务**：让目标物品的下落只能靠打听或搜查得知。

### 历史实验（第三轮，commit 6f53936 及之前；特征 v1、奖励 v1、PPO 环境未江湖化）

以下数字只读自当时的自报日志，未复测，保留作历史标签，**不与当前默认配置比较**。已知的口径问题：

- `changed_recall` 实为**位置**变化召回，不是全部世界事实的召回。
- 动手的误差不能全归因于随机：当时的环境编码遗漏了内力与兵刃锋利（已由 Schema v2 修正），同一输入可以对应必败与必胜。
- 研读与常数持平不代表修习没有可学的动态：进度与学成的技能当时不是预测目标。
- 常数基线取自测试集本身，只能算事后诊断。
- 策略表的“目标达成率”没有区分开局即满足、后来达成与持续守住，也没有永远等待基线；动态模型表与策略表的场景版本、惩罚与模仿权重各不相同，不是同一个实验。

#### 动态模型（第三轮：1500 个程序化世界，一半江湖化，按世界切分）

在**未见过的世界**上，对照“什么都不变”基线：

| 指标 | 环境模型 | 角色模型 | 基线 |
|---|---|---|---|
| 变化的事实被正确预测（召回） | 99.7%（精确率 98.8%） | 93.9%（精确率 92.3%） | 0% |
| 未变化的事实保持不变 | 99.96% | 99.6% | 100% |
| 行动成败准确率 | 97.5% | 94.6% | 77.6%（多数类） |
| 属性变化（伤/毒/制/藏/锁）预测正确 | 82.0% | 82.8% | 0% |
| 未知被错误确定化 | — | 1.3% | — |

成败按操作分项，用 Brier 分（越低越好）对照“按该操作的成功率报常数”：

| 操作 | 环境模型 | 角色模型 | 常数 |
|---|---|---|---|
| 移动 | 0.017 | 0.105 | 0.190 |
| 开锁 | 0.000 | 0.074 | 0.056 |
| 动手 | 0.186 | 0.220 | 0.248 |
| 研读 | 0.035 | 0.043 | 0.034 |

如实结论：

- 角色模型低于环境模型是**正确的**：角色不知道门锁没锁、东西藏在哪，预测理应保留不确定性。
- 动手的胜负取决于私密的内力与带种子的随机，准确率只有 70%；但 Brier 0.186 明显优于常数 0.248，说明模型学到了兵刃、伤、毒对胜负的影响，剩下的随机部分本就不可预测。“受伤”的属性变化只对了 49%，原因相同：伤不伤取决于这一击成不成。
- 角色模型在**开锁上比常数还差**（0.074 对 0.056）：角色常常不知道钥匙配不配，模型却把握过头。这是校准问题，下一步做温度缩放，或把“钥匙是否匹配”的信念作为显式特征。
- 研读与常数持平：研读几乎总能成功，没有额外可学的。中毒样本仍少（测试集 14 例），78% 这个数字不稳。

角色策略在 40 局**留出种子**的程序化世界上（每局 30 分钟游戏时间，2~3 个角色目标互相冲突）：

| 策略 | 平均回报 [95% 自助法区间] | 目标达成率 | 每局冤枉人次数 |
|---|---|---|---|
| 随机 | −0.768 [−0.893, −0.637] | 22% | 9.9 |
| 脚本示范者 | **−0.234** [−0.287, −0.180] | **46%** | 0.05 |
| 模仿学习 | −0.300 | 37% | 0 |
| 模仿 → PPO（25 轮 × 1500 步，熵 0.01） | −0.283 [−0.298, −0.266] | 38% | 0 |
| 软化模仿（标签平滑 0.1）→ PPO（30 轮，熵 0.03） | −0.249 [−0.329, −0.168] | 36% | 0.73 |
| 同上，去掉世界模型预测特征 | −0.235 | 38% | 0.75 |

如实结论（每行 100 个角色局，目标达成率区间约 ±9 个百分点）：

- RLlib 流水线端到端可用；学得的策略**与脚本示范者在统计上持平，远好于随机，但尚未超越示范者**。
- 软化模仿 + 更高的熵确实让 PPO 动了起来（训练回报 −0.99 → 约 −0.45），但更多探索**重新带回了冤枉人**（每局 0.7 次）——−0.2 的惩罚相对于搜身可能带来的收益太轻。
- 两次消融都显示策略**没有利用**世界模型的预测特征（去掉后结果在噪声范围内）。

下一步：用并行 env runner 把样本量提高一到两个数量级；加重冤枉人惩罚或改为“搜身前须有依据”的课程；以 GNN 预测器特征训练并做同一消融；扩大评测局数以收窄区间。
