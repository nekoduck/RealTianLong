# 主持层（GM）设计：以规则内核为底的游戏主持人

目标：在**故事连贯、合理**与**响应速度**上强过 Jenova 的“角色扮演游戏主持人”（Roleplay Game Master），并且更好玩。
验收由用户做（“是不是比那个主持人好玩”），下文的数字门槛是我们自己的工程验收，先于调参定死。

## 0. 对手是什么（调研结论，出处见 §8）

- 纯语言模型主持人，没有规则引擎。按场景路由到 OpenAI / Anthropic / Google / xAI / DeepSeek / Qwen 的模型；自选模型是付费功能。
- “无限记忆” = 全量对话存档 + RAG 检索 + 模型自己维护的台账（世界设定、NPC 名册、剧情线、已知地点、可选数值）。
  台账由模型维护，没有任何机制强迫它与正文一致。
- 它自己承认的弱点：“物品与数值按叙事记账，不是计算出来的”；“即兴发挥容易太顺着玩家，除非你明确要求失败、稀缺和 NPC 的意志”。
- 设计上的好规矩，值得学：不替玩家角色做重要决定、不替玩家说话；写完后果、NPC 反应与世界回应就“停在钩子上”；`GM:` 前缀进入场外模式。
- 延迟没有公开数据。第三方基准里的“首个答案 token 时间”：Claude Opus 5.5 低档约 11.8 秒，Gemini 3.8 Flash 高档约 20.8 秒，
  Gemini 3.7 Flash 低档约 1.2 秒。前沿模型加检索、再加台账更新，首字大概率要好几秒。

## 1. 我们的打法

**规则内核永远是唯一的事实裁判**：谁在哪、谁拿着什么、谁受了伤、谁学会了什么，只能由内核结算得出。
模型只做三件事：

1. **听懂玩家的任何话**：解释器（快模型）。
2. **替 NPC 开口**：内容由各自的认知决定，措辞交给模型。
3. **把本回合写成好读的文字**：主持人之声（叙述模型，流式）。

模型写出的每一句话都要过确定性的语义闸门，闸门能看出的毛病写不进去，写进去的只有修辞。
闸门拦得住什么、拦不住什么（例如言语里否定得不够紧的说法），以 `language/render.py` 头部写明的局限为准。

对手的弱点正是我们的结构性强项：

| 维度 | 纯模型主持人 | 我们 |
|---|---|---|
| 硬事实（物品、伤势、位置、技能） | 模型自记台账，会漂 | 内核结算，零漂移 |
| 谁知道什么 | 靠提示词“别说漏” | 每个角色只有自己的认知图，结构上说不漏 |
| 顺着玩家 | 自认“太顺着” | 成败由规则与随机裁定，嘴上说“我一掌打倒司空玄”也没用 |
| 幕后世界 | 声称 NPC 在你离开时行动 | NPC 真的在跑，事件日志可查，结局时揭晓真相 |
| 首字延迟 | 前沿模型数秒到十几秒 | 目标 p50 ≤ 1.5 秒（§5） |

我们要补的短板（摸底实测，见 §7）：

- 自由输入常常卡死在“你想告诉谁什么？”，或者被误解成别的动作。
- NPC 几乎不说话，只会回答“某某在哪”。
- 叙述回退成干巴巴的事实清单，而且不记得上一回合发生了什么。
- 开场不管输入什么都挨打；主线走到死胡同，没有结局。

## 2. 一回合的数据流

```
玩家输入
  ├─(并行) 解释器：规则快路径（高精度整句命令，0 ms）或快模型 JSON → PlayerMove
  └─(并行) 本 tick 的 NPC 决策（不依赖玩家意图，只读同一版本）
        ↓
  PlayerMove.kind:
    ACT     → 1~3 个内核步骤（“拿起长剑向龚光杰刺去”= TAKE 长剑 → ATTACK 龚光杰），失败即止
    SAY     → TELL/ASK（命题可选），带 social 言语行为与去掉包装的原话
    GESTURE → 带姿态的 WAIT（在场的人看得见），带 social（拔剑 = 威胁，磕头 = 服软）
    ASK_GM  → 场外问答（“我该做什么”“我身上有什么”），只用玩家自己的认知，不推进时间
    META    → /hint /recap /beliefs 等，不推进时间
        ↓
  内核逐 tick 结算（WorldAuthority，幂等、原子提交）
        ↓
  反应 tick：本回合对谁说了话、做了姿态、动了手 → 再走 1 tick（玩家原地），在场的 NPC 当场回应
        ↓
  主持人之声：依据玩家本回合的感知 + 要替 NPC 说出口的话 + 最近几回合的正文 → 流式叙述，逐句过闸门
```

每回合最多两次模型调用：一次解释（快模型；规则快路径命中则为 0），一次叙述（流式）。
NPC 的台词不单独调模型，由叙述调用一并写出（§4.3）。

## 3. 内核与认知的改动（事实契约不变）

- **言语行为 `Social`**：封闭词表，放在 `core/schema.py`，包括 greet thank apologize plead praise threaten taunt insult refuse agree joke comfort explain challenge command farewell remark submit。
  它写进 `Intent.social` / `PerceivedEvent.social`，是修辞层的社交含义，不是事实。
- **自由言语**：TELL/ASK 的命题改为可选。有命题时传递“说法”（听者得到带出处的传闻）；没有命题时只有原话与言语行为。
  原话 `utterance` 只作修辞，永远不产生事实。
- **姿态**：带 `utterance` 的 WAIT 让在场的人亲眼看见（“段誉坐下喝茶”“段誉拔出长剑”）；不带 `utterance` 的 WAIT 照旧无声无息。
- `KERNEL_VERSION` 升到 `kernel-v2`：准入语义变了，旧存档会被版本闸门拒绝，须显式迁移。
  学习层的特征规格不变（`utterance` 与 `social` 不进特征），但新增的 NPC 自由言语候选改变 `CANDIDATES_VERSION`，旧的部署包因此过期、须重训。
  主持体验默认用脚本策略，不受影响。
- **社交线索与态度**（`cognition`）：
  - 别人对我或当众做出的言语行为记为 `SocialCue`。
  - 被当面说话时生成回话义务 `Obligation("reply")`。
  - 每个角色对别人的态度 `attitude ∈ [-3, 3]`：辱骂、威胁、动手使其下降，道谢、求情、赔罪、救治使其上升。
  - 态度只存在于这个角色自己的心里，随认知一起落库。

## 4. 四个组件

### 4.1 解释器（`language/interpret.py`）

- **规则快路径**只收高精度的整句命令：“环顾四周”“等到天黑”“去 + 已知地点”“研读 + 已知物品”等。
  其余一律交给模型。单字关键词（打、下、用、说、学、偷……）不再直接成立。
- **模型路径**：
  - 快模型（`GEMINI_FAST_MODEL`），JSON Schema，只列玩家认识的实体（ID、名字、种类、以为在哪），再附上最近两回合用来消解“她/那人”。
  - 输出 `PlayerMove`，然后逐项校验：实体必须是玩家认识的、签名要合法、路线要按玩家的地图补全。
  - 不合法的步骤丢弃并给出场内说法，而不是反问。
- **没有模型时**退回现有规则解析器，模板模式照常能玩。

### 4.2 NPC 社交层（`agents/policies.py`、`tactics.py`）

优先级，从高到低：

1. 自救、还手、救同伴（沿用）
2. **回话**：按性情 × 态度 × 对方言语行为选回话的言语行为；被问到的事，知道就答（命题取自自己的认知），不知道就说不知道。
3. 回答义务（沿用）
4. **先礼后兵**：敌意目标先挑衅或叫阵，玩家嘴硬才动手，服软可以化解。
5. 各自目标（沿用）
6. **闲谈**：话多的角色在玩家身边会主动搭话，有冷却时间。
7. 查看响动
8. 等待

同时修掉摸底时发现的几个问题：

- 混战中记忆太短，导致 NPC 把中毒的同伴丢在一边发呆。
- 西宗掌门一上来就护着东宗弟子。
- 守卫反复把玩家点住，形成死循环。

### 4.3 主持人之声（`language/narrator.py`）

- **输入**（全部来自已落库的数据，重试写出的是同一回合）：
  - 玩家本回合的感知和事实清单。
  - 玩家原话与解释结果。
  - 本回合玩家听到的每一句 NPC 言语：说话者、听者、言语行为，以及命题——有就给，没有就是闲话。
  - 说话者的说话风格和公开的为人（不含秘密）。
  - 说话者认识的名字（台词只许提这些）。
  - 最近三回合的正文（接续上下文，避免重复）。
- **输出**：
  - 第二人称，80~250 字，NPC 台词写成“某某道：“……””。
  - 不替玩家说新的话、不替玩家做决定，停在钩子上。
- **闸门**：
  - 整段沿用 `check()`。
  - 另加台词闸门：每段引语归属到最近的说话者，里面点名的实体须是说话者认识的，状态词须是说话者相信的；
    归到“你”名下的引语只能是玩家自己的原话。
- **先声后文**（`language/lead.py`）：玩家自己这一步的结果（到了哪、拿到没有、一掌打中没有、说了什么，失败必说原因）
  写成确定的句子，照样过闸门。它和悬念是一对矛盾：结果先说了，模型铺陈“你把心一横，纵身跳了下去……”就没了戏。所以默认迟到才上场：
  - 模型 1.5 秒内交付了第一句，先声不出场，整段由模型铺陈；
  - 超过 1.5 秒还没字，先声顶上、自成一段，玩家不干等；模型不知道它，照常写，几乎逐字重复它的句子略过；
  - 首字因此最迟约 1.5 秒（加上解释与结算），与 §7 的 L1 门槛对齐；实测后按模型的首字分布调这个时限；
  - 另有立即模式（`lead_after=0`）：结算完即交付并告诉模型开头已写好，首字约 0.1 秒，代价是悬念。
- **流式输出**：
  - 逐句生成、逐句过闸门，通过即显示。
  - 违规的句子丢弃。丢了两句以上，或者一句都没通过，就补上模板清单。
  - 违规明细全部记下，供评测统计。

### 4.4 会话（`runtime/session.py`）

- **解释与 NPC 决策并行**：NPC 决策是纯计算，不写存储，场外问答时丢弃即可。
- **请求进度的新字段**：
  - `followups`：多步计划的后续步骤。
  - `reaction`：是否追加一个反应 tick。
- **等待只被要紧的事打断**：有人对我说话、有人对我或同伴动手、有人进出我所在的地点。
- 最近几回合的正文随会话运行态落库，读档后接得上。
- 叙述通过回调流式交给前端：CLI 逐句打印；网页前端（`runtime/web.py`，`python -m tianlong.runtime.web`）经 SSE 逐句推送。
  浏览器只收到玩家该看的文字，真相与 NPC 理由从不出进程。
- **行动建议**（`runtime/suggest.py`）：开场与每回合收尾附上两三句可点的输入。
  - 只凭玩家自己的认知与候选集生成，不剧透；
  - 有人冲我来就先给赔罪与脱身，其次是没看清的、没研读过的、没去过的；
  - 措辞落在解释器快路径的句式上，点了不必等模型。
  - 这补的是纯模型主持人的“空白输入框”问题：新玩家不知从何下手时，也有现成的一步。
- **性能**：去掉没人读的 LangGraph 检查点（它占 NPC 决策耗时的 65~75%）；recall 的输出没人用，跳过。

### 4.5 前后照应（`runtime/continuity.py`）

第一轮代理对照里，评委挑我们最多的是“前后接不上”：钟灵被点了穴、困在大殿，下一幕却毫发无伤地走进崖底，没人觉得奇怪；
段誉挨了一掌，此后再没人提；“等到天黑”被闲聊打断得原地打转；到了结局还问玩家要不要回头。事实本身都对（内核裁定），
错在叙述不知道“玩家以为的”变了。所以每回合拿玩家自己的认知比对“本回合之前以为的 vs 此刻看见的”，写成几句给叙述者的提醒：

- 玩家自己的伤、毒、被制，以及刚好了的伤（说到它们不算状态升级，状态落在玩家身上不算错）；
- 你原以为某人被制在别处，却在眼前见到了他——叙述写出觉察与惊讶，不替谁解释；
- 意外出现或刚走到眼前的人开口时，带上他自己近来的经历，好让他亲口说出怎么脱身、怎么找来的；
- 一路相随的同伴（自己人与要护的人）没跟来；
- 身在何处、身边有谁：无事发生时有模型就写眼前的光景，而不是一句“时间悄悄过去”；
- 抵达结局的那一回合收在余韵上，不再抛出选择；
- 闲扯（没有命题的说笑、随口一句）不再打断等待；此前已知下落的东西再翻出来只说“仍在”，不算又发现一回。

全部只取玩家自己的认知，从不看世界真相：玩家不知道的变化不会出现在提醒里。

第二轮代理对照（加了上面这些之后）评委仍判纯模型主持人全胜。逐句回放闸门日志才看清：叙述模型其实写出了我们想要的句子，
是闸门把它们误杀了——“你心头一跳，她明明被左子穆点了穴道，怎地此刻就在眼前？”因为提醒里没有左子穆、没有“点穴”而被当成
凭空点名与状态升级丢掉；钟灵答“我先去了营地，又绕到后山，一路下来”被当成叙述者替人瞬移丢掉；门楣上刻的“琅嬛福地”被当成
玩家说的话。于是第三轮先治闸门，再补内容：

- 提醒写明是谁制住的（玩家亲眼看见的那一下），并把“被制”列为说到的状态；
- 瞬移只查叙述者自己的口吻，引语里说话者讲自己的来路交给台词闸门；刻着、写着、题作的字不归给任何人；
- 此地叫得出名字的东西、门那头的地点可以点名（“回头是剑湖宫”）；别称里的普通名词（石洞里的“石壁”）不再当作点名了无量玉璧；
- 谈资按条记账（`runtime/talk.py`）：说过一回就不再交给叙述者，NPC 不再每开口就把设定背一遍；
- 玩家问到的人，附上说话者所知的公开来历（`Profile.intro`）；玩家冲着谁说了话、他却没接话，照实告诉叙述者别替他编答案；
- 旁人来到眼前写出他从哪道门过来（“钟灵经断崖来到剑湖畔”），近来的经历优先留着他挨的那一下；
- 等待被打断照实说；伤只在吃力或刚受伤时带一笔；下断崖有经过（藤萝兜住、衣衫刮破）；叩拜写成磕头；
- 提示从玩家所在之处说起（`Scenario.guide_at`），身在崖底不再提开场的事。

第三轮（代理在线逐次作答：引擎每走到一次叙述就停下，代理看着真实的前文作答，与真接模型一样）找错从 22 处降到 14 处、严重的从 1 处降到 0，
盲评仍判纯模型主持人胜。剩下的毛病与第四轮的对策：

- 早先的一幕从短期经历里滚掉了：谁制住了谁、挨过的那一下改从经历记录里找，挨过点穴而此刻能说能走就添一句“后来穴道自己解开了”；
- 身边的人玩家以为的伤势交给叙述者（钟灵受了伤，就别写她轻巧巧地跳来跳去）；
- “我身上还有什么？”是故事里的自问：用故事口吻答、不标“（场外）”、不顺手塞一条攻略；明说“GM：”才是场外；
- 换了说法的谈资也记账；四下看看什么也没翻出来，不再补一句“你仔细查看某处”；出手被挡只说“被对方化解了”；
- 等待还在同一个时辰里就说过了多久，不说“到了酉时”（开场已是酉时）；玩家干等时把行动建议交给叙述者作钩子；
- 外观描写与提示只写看得见的、没人告诉过他的不说（隧道出口会被掩住、玉璧的传闻），凌波微步的方位与《易经》相合。

第四轮找错 18 处（0 严重、5 中等），盲评仍输。评委的例证集中在“回应”与“好玩”：马五德不答“龚师兄是什么来头”，
钟灵不跟着玩家走，后院“什么都没有”（其实有通往后山的小门），几乎每回合都以“你是……还是……？”收尾。追下去是三个真毛病：

- 认知层的 bug：NPC 同一刻的寒暄把同一刻才听见的问话勾销了，所以马五德再也不回话——只认晚于问话的开口；
- 同伴晚一回合才冒出来：同伴在身边时走开多走一个 tick，跟着你的人当场跟上（钟灵随你钻进石缝、石门、隧道）；
- 所见清单只列人与物、不列路：看得见的通道也在所见里（“小门连着后山”，不说能不能走）。

闸门再松一格（仍守住“谁身上有什么”由人事闸门查）：出处里说过的状态换个说法也算、“穴道脉络”不是被制、亲眼到过的地方与近旁东西的别称可点名、
不在身边的同伴玩家惦记着的伤可说；叫阵讥讽时不交谈资；空洞的闲话漏写了不补；结尾不再替玩家列选项。

第五轮找错 14 处（0 严重、6 中等）：马五德答上了“龚师兄是什么来头”，钟灵当场跟着钻进石缝、穿过隧道，盲评仍输。
这一轮的毛病与第六轮的对策：所见里的通道把没去过的那头也点了名（隧道通往澜沧江畔、山径尽头是神农帮营地），改成只点亲眼见过的；
钟灵带着貂挡开掌门的一掌（貂的锋利让她格挡也强），貂的锋利调低——咬得中龚光杰、挡不住掌门；一路跟过来的同伴不再“竟然又出现在身后”；
伤只在吃力或刚变时交给叙述者（每回合都给，模型就每回合都写胸口发闷）；玩家的姿态漏写不补；台词被丢时接着它的“她说完……”一并略过；
当面动手却没开口的人（左子穆）可以顺口喝一声——评委一再说对手“从不开口”，这给人物一副嗓子，不给新的事实。

## 5. 模型接入（`language/llm.py`）

- **两个角色**：
  - 快模型 `GEMINI_FAST_MODEL`（解释用，默认 flash-lite 档）。
  - 叙述模型 `GEMINI_MODEL`（默认 `gemini-3.8-flash`）。
  - 型号不可用时退回 `-latest` 别名。
- **速度相关设置**：
  - 显式设置思考档位：3.x 用 `thinkingLevel`，叙述取 `low`，解释取最低档。2.5 系列用 `thinkingBudget: 0`。
    接口拒绝这个字段时去掉它重试一次。
  - 保持长连接（每个线程一条），不再每次重新握手。
  - 叙述走 `streamGenerateContent?alt=sse`。
  - 每次调用记下首 token 时间与总时间。
- **首字对冲**（`language/hedge.py`）：公开数据里 3.8 Flash 低档首字中位数约 2.2 秒、p95 约 5.3 秒，而且它不支持 minimal 档。
  单靠它，§7 的 p50 ≤ 1.5 秒达不到，长尾更会拖垮体验。于是叙述模型包一层 `HedgedLLM`：
  - 主模型 `GEMINI_HEDGE_AFTER` 秒（默认 2.5）内没吐出第一段字，或提前出错，就把同一请求并发给快模型；
  - 两路赛跑，先出字的一路讲完整段，另一路作废（不交付任何文字，下一段字到达时关连接）；
  - 读流在常驻线程里，每线程的长连接跨回合复用；
  - 平时照样用主模型的文笔，只在它迟到时请替补，p95 被压到“时限 + 快模型首字”以内；
  - 时限按实测调，`0` 关闭。
- **磁盘缓存**：默认关闭（同一提示词会返回同一段文字，读起来重复），只在测试和评测里显式打开。
- **离线**：`ScriptedLLM` 按脚本回放、可模拟延迟与流式，供测试和评测管道使用。

## 6. 剧情与内容（无量山第一幕）

- **开场**：龚光杰先叫阵（“你笑什么？下场比划比划！”），玩家可以赔罪、硬顶、求人、开溜。钟灵在梁上起哄。马五德打圆场。
- **说话风格与谈资**：每个 NPC 有说话风格，有“知道哪些江湖掌故”，玩家问得出东西。
- **玩家目标与提示**：段誉的目标（保命、离开无量山、别连累钟灵）驱动 `/hint` 与“我该做什么”。
  提示按需逐级给出，不再一开场就把通关步骤全写出来。
- **结局**：抵达澜沧江畔即第一幕终。
  - 终章：模型据事件日志写一段收束。
  - 真相揭晓：你以为的 vs 实际发生的，例如私奔那对后来怎样、钟灵为你做了什么。这是纯模型主持人给不出的东西。
- **节奏**：伤势不再永久，休息可以缓解；守卫不再把人点住不放。

用 `scripts/bench_gm.py` 跑（有 `GEMINI_API_KEY` 时用真模型、空缓存；无密钥时用 `ScriptedLLM` 跑通管道）。

两边跑同一批脚本，自动指标照上表算；另由第三方模型盲评“哪个更连贯、更合理、更想继续玩”，作为辅证。
最终裁决归用户。

### 评测细则（`scripts/bench_gm.py`）

- **脚本**：`scripts/bench_probes.json` 分四组——整局游玩（从大殿到澜沧江畔，说话、姿态、行动、等待、提问混杂）、
  60 句花样输入（R4）、15 句瞎编前提（C2）、10 句按规则不可能成功的企图（R1）。
  后三组每条都从全新会话（`build_wuliang(seed)`）出发，先走 `setup`；`require` 不成立的判为铺垫失败，不计入分母。
  M4 起它是 v2（普通人版，`"variant": "wuliang"`：跟随型 38 句、留守型与夜遁型各 24 句、60 / 20 / 12 条探针，见 commoner_plan §8.1），
  文件里的 variant 决定场景；旧版原样改名为 `scripts/bench_probes_duanyu.json`（`--probes` 指过去即 run1–6 的评测）。
  新指标的逐回合字段与算法在 `scripts/bench_metrics.py`；`--latency-sim` 按公开分布模拟 L1/L2（`scripts/bench_latency.py`），报告标注“模拟”。
- **计时**：L2 是 `turn()` 外面的挂钟。L1 取第一次 `on_text` 回调（会话支持时），其次取 `TurnReport.first_text_ms`，
  都没有就等于 L2；报告写明几成回合真的量到了流式首字。只计整局游玩与探针本身，不计铺垫。
- **R4**：推进了世界、或被当作问主持人/元指令作答，算接住；追问（听不懂、反问）与异常算没接住。
  “不误解”只拿每条的 `expect` 类别做参考，不设门槛。
- **C1**：每回合之后对世界头版本跑 `kernel.violations()`，再加上结算中抛出的 `InvariantViolation`。
- **C2 / R1**：按世界真相自动判定。声称之物在回合后成立、回合前不成立，而且玩家本回合有成功的非言语行动，才算被接受或得逞；
  声称之物包括持有、学成、身处、交到某人手里、被制、受伤。R1 的门槛同为 0（§1“顺着玩家”；这 10 句按规则都不可能成功）。
  另有词法启发式“叙述断言得手”：先去掉引号里玩家的原话，某一句里出现声称之物且没有否定词即算。它只作旁证，不进结论。
- **G1**：丢弃句数 ÷（丢弃句数 + 交付句数），只算模型叙述的回合。会话没交出丢弃句数时，以违规条数近似，报告注明。
- **N1**：只数推进了时间的回合（追问与场外问答不推进时间，NPC 无从开口）。“在场”按真相判定：回合前或回合后，玩家所在地有 NPC。“开口”指以下任一：
  - 本回合 NPC 在那里说了话（TELL/ASK 事件）；
  - 玩家听到了 NPC 的言语；
  - 会话交出了要说的台词。
- **F2**：整局游玩里相邻两段正文的字符 4-gram 重合度，即后一段的 4-gram 有多少已出现在前一段（去掉标点与空白），取均值。
- **P1**：只算交付给玩家的文字，是词法启发式。命中两种说法：归到“你”名下、又不是玩家原话的引语；“你决定/你心想”一类。
  闸门拦下的 `puppet` 违规另列，不计入。
- **对照组**：`PureLLMGM` 的系统提示是由场景生成的全知世界圣经（路线与单向/夜现规则、人物的为人、秘密、目标与所在、物品所在、
  玩家目标、结局）加上 §0 的主持规矩。每回合发出完整对话与新输入，流式取回复，同样计时。
  它没有内核可查：C2/R1 在 `--judge` 时由独立评审调用判定（严格 JSON，无效判定不计入），否则只报词法启发式。
  `--judge` 还对整局游玩做一次盲评。A/B 顺序：run7 起的 3 个面板（两个种子 + 玩家代理）从派生的起点轮流换边，两种先后都出现；
  旧版 run1–6 照旧由种子固定打乱。终章只把主持人的收束交给盲评，真相揭晓与“那一夜你没看见的事”纪事是落幕后另起的卡片，对照组没有对应物。
- **模型**：`--llm auto` 用环境里的真模型，缓存关闭；没有密钥则退回 `scripted`。`scripted` 的报告开头注明不是真模型，不作验收依据。
  评审默认与叙述同一型号；要让第三方型号来评，设 `GEMINI_JUDGE_MODEL`。

## 8. M2-a spike 结论：驱力层要用到的内核事实

在真实的 Kernel / WorldAuthority 上逐条核对（旧版无量山 + 只在 spike 里加的阿顺），**内核一行不改**，不成立的都改在驱力条件上。

**tick 语义**：同一 tick 所有 NPC 在同一个世界版本上决策；内核按先手值逐个结算意图。
先手值 = 基值 + 姿态（CAREFUL −0.2，ROUGH +0.2）+ 0.5·敏捷 + 抖动 [0, 0.1)。
基值为：ATTACK .7；USE / TAKE .6；TELL / ASK / GIVE / PUT / 上锁 .5；MOVE .4；INSPECT .3；STUDY .2；WAIT 0。
第 t tick 的 TELL 从 t+1 起才影响别人的选择。

| # | 假设 | 结论 | 驱力层的对策 |
|---|---|---|---|
| 1 | 先验里的言语能把态度折叠到 +1 | **只在听者的认知里成立**（GREET 只在态度为 0 时 +1） | 段誉、马五德喜欢阿顺，就在**他们**的先验里放一条阿顺向他们 GREET / THANK 的感知。马五德的叮嘱在阿顺先验里若记成 COMMAND，会让阿顺对马五德 −1，所以改记为马五德自己的 SELF 先验或 EXPLAIN。先验至少比开场早 4 tick，否则留下待回应的义务。段誉自己的 GREET 也记为 SELF 先验，免得 17:40 再打一次招呼。不需要在 found() 里写 regard。 |
| 2 | NPC 夜里 INSPECT 玉璧能看见石缝 | **成立**，从 19:00（内核的夜）起；INSPECT 剑湖畔本身也行，旁观者得到同样的事实 | 进 shidong 之前 `route_to(langhuan)` 为空：explore_crack 要先 `Go(shidong)` 再 `Go(langhuan)`。石缝在 19:00–19:39、月出之前就能发现，只是叙述要自洽。 |
| 3 | 同一 tick 走进来的人听得见正常音量的 TELL | **不成立**（同敏捷时，只有他的 MOVE 先结算才听得见）：阿顺 0/60，钟灵（敏捷 .8）56/60 | 同一 tick 离开的人照样听得见。在场摆出的 WAIT 带字姿态 60/60 被看见。隔壁房间约 5% 只听到无内容的响动。私奔那对的 `company[ashun]` 等于下一次决策 tick，所以 hush 在 t+1 才触发。**对策二选一**：murmur 改成 Pose（WAIT + 字 + REMARK），走进来的人当 tick 就看得见（相识账本须接受 WAIT 上的原话）；或者 hush 推迟一 tick，只在外人的 `company.since < now` 时触发，since == now 时不拦 murmur，冷却 1。 |
| 4 | 左子穆的 demand 能抢在还手之前 | **部分成立**：t0 咬 → t0+1 demand（同 tick 的 ATTACK 先结算）→ t0+2 USE → t0+3 AGREE | 照原表跑，钟灵与龚光杰互相还手，龚光杰 19/19 局以中毒 + 被制告终。加两条 VETO 后：中毒 0/20，被制 0/20，解药从没被搜走。一条是钟灵的 `hold_bite`：不再打她看见已中毒的人，交易之后不再打龚光杰，除非挨打。另一条是龚光杰的 `defer`：听见师父对钟灵开口后不打她。仍有 5/20 局不成：第一口被格开 → 没中毒 → 没有 demand；种子 14 是线索缓冲被挤掉。龚光杰的外伤不会好（内核没有自愈），“痊愈”指不再中毒。可选的左子穆 `warn`：对盟友出手没得手时，改为 THREATEN。**VETO 的时间窗一律以该驱力自己的标记计**，不看线索或经历：线索上限 8 条，经历 12 条。 |
| 5 | USE / MOVE / ATTACK 上的原话，在场者都感知得到 | **成立**，`public_view` 保留原话与 social | 被看见的情形：ATTACK 成功或被格开、USE 成功或无效、MOVE 成功（出发地与目的地都看见）、WAIT 带字、INSPECT、TAKE、GIVE。**例外**：<br>• 无声失败：够不着、没什么可学、MOVE 时同 tick 早先已被制；<br>• MOVE 在门口失败：单向、门锁，重建的视图里没有原话；<br>• 不带字的 WAIT、耳语 TELL。<br>只有 TELL / ASK / WAIT 产生 SocialCue，其余 op 的原话只进 12 格的经历缓冲。所以必须被听见的台词只挂在不会无声失败的 op 上，否则另起一个 TELL 或 Pose。truce 与相识账本途径 2 必须读经历或任何 `PerceivedEvent.utterance`，不能只读线索。 |
| 6 | 钟灵看见段誉经断崖下去后，能沿断崖跟下去 | **成立**：她看见他的 MOVE 与原话，相信他在 jianhu，路线经 d_cliff，DEFEND 让她在 t+1 移动 | 没看见的跳崖，靠探索约在 t+7 到达 jianhu。**龚光杰也会在 t+1 跟着跳**：give_up 必须在 t+1 抢先，他对跳崖的 SIGHT 那时已经有了。 |
| 7 | 研读学成对旁观者可见 | **不成立**：旁观者看到的学成与没学成是同一个 `PE(study, success)`，没有事实也没有理由；难度对段誉隐藏，他预见不到哪一次学成 | 凌波微步要到交手时才以 `evaded` 显出来。**对策**：URGENT、once 的 `exult` 驱力，自己已会 evasion 时，学成后一 tick 摆 Pose“妙哉……”。钟灵的 `grab` 挂在这个 Pose 上：她看见他 STUDY 之后，又收到段誉的 WAIT 线索。`leave` 排在 exult 之后。 |
| 8 | 搜人（`_hostile(until=subdued)`） | 相信对方在哪就去；否则去最近的、20 分钟内没看过的地方；只有这种地方都没了才打听（实际上从不打听） | 在后山 2 tick 就找到段誉，立刻出手，受伤的段誉被制。没看见的跳崖：18:48 他自己**探索下了断崖**，give_up 从不触发。`_blocked_doors` 加上认为单向的门的子类能挡住（四处转，最后困在 yading）。60 tick 里没问过一次路。flee 的“3 tick 内挨过打”约 60 分钟后失效（经历被挤出）。同 tick 的 ATTACK（.7）先于段誉的 MOVE（.4），开局就出手的追兵逃不掉。**对策（只在驱力层）**：<br>• hunt 不知下落时先 ASK 在场的人，再用 drives.py 里 MartialTactics 子类的 `_hostile`，其 `_blocked_doors` 加上认为单向的门；<br>• give_up 在找遍（困在 yading）时也触发；<br>• flee 改看在场的、态度 ≤ −2、没中毒也没被制的人；<br>• corner 每次遭遇一次。 |
| 9 | Choice 能带原话 | **今天不能**：Choice 只有 index / rationale / tag / social / free；free 只给 TELL / ASK；原话只由 `npc_graph.express` 给有话题的 TELL / ASK 生成 | `Orchestrator._share_the_floor` 把被压下的 CHATTER 改写成光秃秃的 WAIT，丢掉原话与 social；只有 social 的 WAIT 谁也看不见。**对策**：<br>• `Choice.line` → NpcState → express，任何 op 有 line 都优先用它；<br>• 驱力的选择从不标 CHATTER；<br>• 每个 Pose 都带字（叩首每次都带）；<br>• line 在 `chosen()` 之后挂上，不挂在 Candidate 上。 |
